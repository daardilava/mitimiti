## App Privacy (App Store Connect › App Privacy)

Based on what the code sends and on [privacy.es.ts](../src/i18n/legal/privacy.es.ts). **Tracking: No** for every
type (no ads, no IDFA, no data brokers), so no App Tracking Transparency prompt is needed.

**Do you collect data?** Yes.

| Apple data type | Why it's collected (who) | Purposes | Linked to user | Tracking |
| --- | --- | --- | --- | --- |
| Contact Info › **Name** | Account and couple profile (Clerk, Supabase; from Google/Apple sign-in) | App Functionality | Yes | No |
| Contact Info › **Email Address** | Account, sign-in codes (Clerk) | App Functionality | Yes | No |
| Identifiers › **User ID** | Clerk id, also used as the RevenueCat app user id (`Purchases.logIn`) | App Functionality, Analytics | Yes | No |
| Purchases › **Purchase History** | Subscription status (RevenueCat, Apple) | App Functionality, Analytics (RevenueCat requires both) | Yes | No |
| Financial Info › **Other Financial Info** | Expenses, payments, budgets and the balance between the two of you (Supabase) | App Functionality | Yes | No |
| User Content › **Photos or Videos** | Receipt photo sent to Anthropic by Escanear; not stored by MitiMiti | App Functionality | No | No |
| User Content › **Other User Content** | Expense descriptions and the change history (Supabase) | App Functionality | Yes | No |

**Not declared, and why:**

- **Audio Data:** Dictar uses Apple's speech recognition (`expo-speech-recognition`); the audio goes to Apple, never
  to MitiMiti or a third party of ours. Only the text you confirm is saved, and that's already covered by Financial
  Info / Other User Content.
- **Diagnostics, Usage Data, Location, Contacts, Browsing/Search History, Sensitive Info, Health:** the app has no
  analytics or crash SDK and asks for none of these.
- **Payment Info:** Apple processes the payment; the app never sees card data.

Notes:
- The receipt photo is processed on request and not stored by us, which on its own would fall outside Apple's
  definition of "collected". It's declared anyway, unlinked, because Anthropic may keep API inputs for a limited
  time, and the Escanear consent step already names Anthropic: being conservative here avoids a mismatch with that
  screen.
- Clerk logs IP address and device for sign-in security (privacy §2). Apple has no separate IP data type; it's
  covered by the account data above.

## App Review information (App Store Connect › version › App Review Information)

**Sign-in information:** the reviewer can't receive Clerk's new-device code (Device Trust asks for an email code the
first time a password sign-in comes from a new device). Clerk can't exempt one user. Options:

1. **Recommended:** turn off Device Trust in the Clerk dashboard (production) › **Protections** while the build is in
   review, and turn it back on after approval. Note the dates in [PLAN.md](PLAN.md).
2. Create the demo account with an email inbox you can read, and answer quickly if App Review writes about the code.
   It's slower and risks a rejection under 2.1 (incomplete information).

**Demo accounts (two, because the app needs a couple):**

1. In the production app (Play internal build or TestFlight), sign up as `review.mitimiti+a@…` (an address you
   control), create the couple, and invite the partner.
2. On a second phone, or after signing out, sign up as `review.mitimiti+b@…` and join with the code.
3. Add a handful of expenses and one payment from both accounts, so the balance and Summary aren't empty.
4. Give App Review account **A** only. Leave **B** alone during review.
